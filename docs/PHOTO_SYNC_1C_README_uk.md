# Star Club — фото товарів з 1С та картки пропозицій

Змінено тільки сайт (src/index.js, public/app.js, public/admin.js, public/styles.css, public/index.html, public/admin.html). База, історія чеків, конфігурація .cf, налаштування Railway та старі BSL-модулі у проєкті не змінені.

## Факт про передачу з 1С

Фото з картки 1С не з’явиться в сканері лише через редеплой сайту. Бінарний файл повинен потрапити через POST /api/1c/products/image. Якщо фото не знайшлося в існуючому реквізиті 1С, старий синхронізатор мовчки його пропускав. Додатковий повний файл `StarClubIntegration_20261018_PHOTO_SYNC_DIAGNOSTIC_FULL.bsl` має розширений пошук у реквізиті `Файл` (використовуваному в деяких 1С-сховищах), звіти про невідправлені зображення та діагностику одного товару.

Цей файл створено на основі останнього раніше підготовленого модуля із підтримкою лімітів кількості. Перед заміною модуля у клієнтській 1С порівняйте його з реально встановленою версією — під час поточних дій клієнтська 1С не була доступна для перевірки й тестування.

### Перевірка конкретного товару

Після встановлення модуля в тестову 1С виконайте:

```
StarClubИнтеграция.StarClubПеревіритиФотоОдногоТовару("ЦБ000005742");
```

Якщо з'явилося `успішно відправлено`, перевірте сканування відповідного штрих-коду в Mini App.

Якщо з'явилося `фото не знайдено стандартним пошуком`, потрібні фактичні реквізити та місце зберігання зображення в цій конфігурації 1С — це НЕ свідчить про помилку CSS або сканера.

### Адміністративна read-only діагностика на сайті

GET `/api/admin/catalog/product-photo-status?code=ЦБ000005742` із наявною авторизацією адміна відповідає:
- `photo_received_from_1c: true` — бінарне фото вже записано у Star Club;
- `false` — його ще не отримано;
- `image_url` — чинна адреса фото/резервного зображення.

Сканер і пропозиції використовують фото 1С за умови, що воно передано, якщо власну фотографію пропозиції не задано.

### Перед розгортанням

Резервна копія живої PostgreSQL бази Railway повинна бути доступна у R2. Не видаляйте Railway volume/DB і не задавайте нову порожню DATABASE_URL. Замініть лише файли сайту, перевірте `npm run check` та повторіть синхронізацію товарів/фото з 1С (без очищення каталогів).

Фото у R2 backup потраплять лише після того, як PostgreSQL зберігатиме відповідні нові записи і відбудеться наступний backup. На живій Railway/1С ці кроки під час підготовки архіву не виконувалися.
